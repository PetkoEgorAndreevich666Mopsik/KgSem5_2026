# Лабораторная работа 5. Mesh Pipeline

## Запуск

В CLion откройте `KG_Sem5_Laba5` как CMake-проект и соберите цель `CG_Sem2` в конфигурации Debug. Нужны MSVC x64, Windows SDK с DXC и Assimp 6.0.5 в `C:/assimp/assimp-6.0.5`. CMake скачивает DirectStorage 1.3.0 из NuGet и размещает DLL и скомпилированные шейдеры рядом с EXE при сборке в `cmake-build-debug`.

Запустите `cmake-build-debug/CG_Sem2.exe`. Нажмите **NumPad 5** или выберите **Settings → Scene → Mesh Pipeline**. NumPad 1–4 открывают сцены предыдущих работ.

## Демонстрация

- **Color meshlets** переключает обычный текстурированный материал и окраску блоков. Силуэт модели и расположение треугольников сохраняются.
- **Single meshlet** и ползунок **Meshlet** оставляют один блок. Отключите флажок, чтобы увидеть модель целиком. Блоки на противоположной стороне можно осмотреть вращением модели.
- **Model rotation** поворачивает сундук. Для камеры используйте WASD и перетаскивание правой кнопкой мыши вне окна настроек.
- Вкладка показывает **71 932 вершины, 103 330 треугольников и 3 278 meshlets**, а также результат загрузки через DirectStorage.
- Для Mesh Pipeline требуются Mesh Shader Tier 1 и Shader Model 6.5. При отсутствии поддержки интерфейс сообщает об этом, а сундук отрисовывается через обычный индексный конвейер.

## Формат геометрии и отрисовка

В `src/Meshlets.cpp` исходные треугольники идут в том же порядке в пределах каждого подмеша. Блок вмещает до 64 вершин и 126 треугольников. Списки вершин привязаны к исходному буферу, поэтому общие границы читают одинаковые координаты. Разбиение сохраняет границы материалов.

Mesh Shader получает четыре буфера через SRV:

| Буфер | Элемент |
| --- | --- |
| Вершины модели | Позиция, нормаль, касательная, бикасательная и UV, 56 байт |
| Meshlets | Смещения и количества вершин и треугольников, 4 × uint32 |
| Ссылки на вершины | Глобальный индекс вершины, uint32 |
| Треугольники | Три 8-битных локальных индекса в uint32 |

`src/RenderingSystem.cpp` создаёт Root Signature и Mesh PSO для существующего G-buffer. В `src/DirectXApp.cpp` один вызов `DispatchMesh` запускает группу потоков на каждый meshlet в указанном диапазоне. В `src/mesh_pipeline.hlsl` группа вызывает `SetMeshOutputCounts` с фактическими размерами блока и передаёт преобразованные вершины в общий `PS_Geometry`.

## DirectStorage

`src/DirectStorageReader.cpp` читает FBX и две текстуры очередью DirectStorage. После события завершения проверяется статус запросов. Assimp и WIC разбирают полученные байты в памяти, затем Direct3D 12 загружает готовую геометрию и текстуры на GPU. При ошибке DirectStorage приложение сообщает о ней в настройках и использует обычное чтение файлов.

Сундук и текстуры выпустил Rico Cilliers под CC0. [Treasure Chest, Poly Haven](https://polyhaven.com/a/treasure_chest)

## Проверки

`ctest --test-dir cmake-build-debug --output-on-failure`

Тесты восстанавливают все треугольники из meshlets и сравнивают индексы и порядок вершин с исходником, включая неполные блоки. Отдельные тесты сверяют байты FBX и текстур после чтения через DirectStorage и создают Mesh PSO на совместимой видеокарте.
